# 0.12.2 实际写作验收

## 验收范围

以本地 0.12.1 安装实例及用户授权的私有小说资料进行实际操作，再用修复后源码与数据库副本复验。小说正文、设定、模型密钥、数据库及生成结果不进入 Git。

* 人物与世界条目：写入后读取，逐项比较正文一致性。
* 大纲：全书总纲保持原有正文，补充卷纲和分章卡，并关联首章。
* 写作：由产品内部 Writer、Reviewer、Actor 执行，检查正文实际落库及审校修改。
* 大纲 AI：完善、节奏检查、章节拆分、根据正文更新，均验证返回候选后没有自动修改数据库。
* 前端确认：拆分候选只有点击创建子节点后才落库。

## 复现与修复

| 症状 | 修复边界 |
| --- | --- |
| 本地 HTTP 页面 JavaScript 被识别为纯文本，页面空白 | SPA 静态资源响应固定 JS、CSS、WASM 媒体类型 |
| 长全书总纲被 8,000 字符上限拒绝 | 大纲 AI 输入与候选上限提高至 48,000；候选溢出明确报错 |
| 上游调用失败显示内部错误 | LLM 客户端归一化供应商失败，保留安全错误消息 |
| 世界条目有正文却显示 0 Tokens | 服务层根据正文计算衍生指标 |
| 故事记忆工具显示未注册 | 前端工具目录、消息注册及翻译补齐 |
| 等待计划结果时提前显示空结果警告 | 只有完成或返回结果后才判断空计划 |
| 空白章节不能初始化，Agent 尝试删除重建 | 章节编辑与审批预览共享空章初始化语义；非空正文拒绝空锚点 |
| 长篇拆分缺少分批数量与阶段要求入口 | UI 支持 3/5/8/10/15/20 章及补充要求 |
| 节点切换后旧异步请求可能回填候选 | 取消旧请求并核对请求身份 |

## 实际模型调用结果

使用本地已有 `cline-pass/mimo-v2.6-flash` 配置。数据仅代表这次运行，不是性能 benchmark。

| 操作 | 结果 | 耗时 |
| --- | --- | --- |
| 长总纲完善（明确要求精简候选） | HTTP 200，1,685 字符候选 | 101.8 秒 |
| 卷纲节奏检查 | HTTP 200，5 项问题 | 38.5 秒 |
| 三章拆分 | HTTP 200，3 项候选 | 84.1 秒 |
| 根据正文更新章节大纲 | HTTP 200，523 字符候选 | 19.8 秒 |

所有操作前后大纲记录一致。另一次无长度约束的长总纲完善遇到上游失败；本版正确返回可重试错误，不能保证第三方服务永不超时。
